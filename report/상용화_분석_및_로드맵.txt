# Rune Puzzle Tactics 상용화 분석 및 로드맵

이 문서는 게임 상용화를 위해 현재 구현된 상태를 점검하고, 부족한 요소(에셋, 코드, 비즈니스 로직 등)를 분석하여 구체적인 TODO 계획과 필요한 에셋 리스트를 정리한 파일입니다.

---

## 1. 현재 구현 상태 요약 (Current State)

### 주요 변경 완료 사항
- **영웅 등급 단일화**: 5명(속성당 1명) 영웅 모두 ★1단계 `R` 등급으로 통합 완료.
- **속성 시스템 개편**: 몬스터는 모두 무속성(`monsterElement = null`), 영웅 속성과 매칭 룬 간의 "시너지 배율(Rune Synergy)"로만 속성 피해를 계산.
- **영웅 교체 UI 단순화**: 자물쇠 슬롯(🔒) 대신 공유 가능한 `+` 버튼 슬롯(`PartySlots`)으로 변경. 탭 시 BottomSheet 영웅 선택창(`showHeroPickerSheet`)이 호출되어 로비, 파티 탭, 스테이지 준비 모달에서 공용으로 사용.
- **번개 속성명 변경**: 기존 Yellow 속성이 Lightning(번개)으로 변경됨 (코드 내부 식별자는 `light` 유지).
- **몬스터 다변화 (텍스트)**: 별도의 에셋 추가 없이 스테이지 번호 기반 결정론적 알고리즘으로 이름(Cave Slime, Stone Maw, Ancient Guardian, Void Spawn)과 등급 접두사(Elite, Elder)를 표시하도록 수정.
- **공용 위젯 분리**: `party_slots.dart` 및 `party_editor.dart`로 로직 공유화 완료.

## 2. 상용화 관점에서의 결함 및 부족한 요소 (Gap Analysis)

### A. 에셋 부족 문제 (Asset Shortage)
현재 프로젝트 내 `assets/` 디렉토리에는 약 5,500개 이상의 이펙트 프레임 파일과 165개의 사운드 파일이 존재하지만, **코드에서 실제로 사용 중인 에셋은 극소수**입니다.
1. **몬스터 에셋 부족**:
   - 현재 구현된 몬스터 애니메이션은 오직 슬라임(`assets/sprites/monster/slime/`) 뿐입니다.
   - 이름은 'Ancient Guardian' 등으로 다양하게 바뀌지만 비주얼은 모두 녹색 슬라임 하나로 고정되어 있어 상용화 시 시각적 몰입감이 크게 떨어집니다.
2. **이펙트 에셋 미활용**:
   - `assets/effects/` 하위에 방대한 이팩트 스프라이트 시트(스펠, 타격, 폭발 등)가 있지만 퍼즐 매칭이나 보스 공격 시 거의 연출되지 않고 있습니다.
3. **사운드 에셋 미등록**:
   - 사운드 파일은 165개가 존재하지만 `GameAudioService.effectAssets`에 등록되어 재생되는 효과음은 단 13개에 불과합니다.

### B. 비즈니스 로직 및 BM 부족
1. **광고(AdMob) 설정**:
   - 배너 광고 및 보상형 광고의 ID가 구글 테스트 ID(`ca-app-pub-3940256099942544/...`)로 하드코딩되어 있습니다. 상용화를 위해서는 실제 AdMob 콘솔의 광고 단위 ID로 교체되어야 합니다.
2. **진행도 저장소 검증**:
   - SQLite 기반의 진행도 저장(`SqliteRuneProgressStore`) 기능이 구현되어 있으나 디바이스 환경에서의 데이터 마이그레이션이나 저장 안정성이 완벽히 검증되지 않았습니다.
3. **가챠 및 영웅 영입 밸런스**:
   - 영웅 획득 재화 밸런스와 광고 시청 보상 밸런스가 완전한 플레이 테스트를 거치지 않아 경제 시스템이 붕괴될 위험이 있습니다.

## 5. 보안 가이드 준수 (Security Reminder)
- 릴리즈 빌드 서명 키(`key.properties`, `upload-key.jks`)는 절대로 public Git 저장소에 커밋되지 않도록 `.gitignore` 상태를 철저히 유지하십시오.
- Firebase `google-services.json`은 공개되어도 안전한 파일이나, Google Cloud Console에서 API 키에 대한 사용 제한(HTTP 리퍼러, 안드로이드 패키지 명 제한)을 걸어두는 프로덕션 보안 작업을 상용화 전에 필히 완료해야 합니다.
